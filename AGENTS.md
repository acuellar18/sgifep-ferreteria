# AGENTS.md

SGIFEP — Ferretería El Puente. Repo único, 3 proyectos npm independientes (sin `package.json` raíz): `landing/` (Vite HTML+CSS multi-página), `sistema/frontend/` (React 18 + Vite) y `backend/` (Express + MySQL). SQL en `database/scripts/`; migraciones en `backend/migrations/`.

## Comandos críticos (no adivinar)
- `npm start` (backend/, puerto `PORT` default 3000).
- `npm run seed` (backend/): idempotente; crea catálogos y garantiza `admin`/`admin123` ACTIVO con rol `administrador`. **Reejecutar resetea la contraseña a `admin123`.**
- Migraciones: `npm run migrate` (backend/) recorre `backend/migrations/*.sql` (`003`–`021`) **sin tabla de control**; reejecuta todo. Cada SQL debe ser idempotente. Ignora `migrations/reversos/` (manuales). BD nueva: `database/scripts/002_usuarios_roles_departamentos.sql` una vez, luego `npm run migrate`, recién `npm run seed`.
- Compras demo: `npm run reiniciar-compras` (borra proveedores/productos/compras/órdenes/pagos/movimientos + seed; conserva usuarios/roles/categorías). `npm run seed-compras` requiere migraciones previas. Reglas/orden: `backend/README_COMPRAS.md`. Verificar: `npm run verificar-compras`; probar: `probar-permisos-compras`, `probar-reportes-compras`, `probar-inventario`, `probar-categorias`, `probar-productos`, `probar-movimientos`, `probar-clientes`, `probar-facturas`, `probar-caja`, `probar-pos`, `probar-perfil`. Los `probar-*` levantan Express efímero (no hace falta `npm start`) pero necesitan BD migrada; `verificar-compras` habla directo con MySQL.
- Landing: `npm run dev` (`landing/`, 5173); build `npm run build` → `landing/dist` (Express sirve raíz; si falta responde aviso de texto).
- Sistema: `npm run dev` (`sistema/frontend/`, 5174, base `/usuarios/`, proxy `/api` → `http://127.0.0.1:3000`). `predev`/`prebuild` corren `scripts/sincronizar-sidebar.mjs`: edita `src/styles/sidebar.css` (origen), no `public/assets-modulos/sidebar.css` (copiado). Producción: `npm run build:deploy` (build + copia a `backend/public/`; `sistema/frontend/scripts/deploy.mjs` copia `dist/assets`, `index.html`, `login.html`, `modulos.html`, `img/`, `public/assets-modulos`; **no copia** carpetas HTML estáticas como `public/{compras,facturacion,despacho,reportes}/*.html`).
- No hay framework de test/lint/typecheck. Verificar con `npm run build` en frontends, `node --check <archivo>` en backend, y los scripts `verificar-*`/`probar-*`.

## Backend y base de datos
- `backend/db.js` carga `backend/.env` por `__dirname` (independiente del cwd); exporta pool singleton. `.env` no versionado.
- Claves `.env`: `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME=sgifep_db`, `PORT`. En dev se usa fallback `config/auth.js`; **en producción `JWT_SECRET` obligatorio** (backend no arranca sin él).
- `database/scripts/schema.sql` es referencia (crea `sgifep_ferreteria`, no coincide con `sgifep_db`); no usar para levantar entorno.
- Migraciones `004`, `005`, `006`, `008`, `009` usan `CREATE INDEX IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` (MariaDB); en MySQL 8 pueden fallar. `migrate.js` soporta `DELIMITER` para triggers.
- Layering obligatorio: `routes/` (HTTP + permisos) → `controllers/` → `services/` → `repositories/` (solo SQL); validación/serialización en `dtos/`.
- Solo `/api/login` y `/api/reset-password` públicos. El resto requiere `Authorization: Bearer <token>` (`autenticar`). Compras y Usuarios usan `requerirRoles`; Inventario usa permisos granulares (`permisos`/`permisos_rol`) vía `cargarPermisos`/`requerirPermiso` (`inventario.productos.ver`, `.crear`, `.editar`, `.eliminar`, `.ver_costos`); Facturación igual (`facturacion.*`, `seguridad.auditoria.ver`). Cobros/devoluciones de crédito: `facturacion.cobros.registrar` / `.devolver`. Tokens de 8 h.
- Login: máximo 5 fallos por usuario/IP en 15 min (`intentos_login`); contraseñas 8–72 con mayúscula, minúscula y número, sin datos personales; headers de seguridad en `middlewares/security.middleware.js`.
- Roles/departamentos se leen de BD; nunca hardcodear. Usuario puede tener varios roles (`usuario_roles`). El frontend decide visibilidad por nombre en `src/utils/permisos*.js`; la autoridad real es backend.
- **Stock/costo solo cambia por `trg_movimientos_before_insert`** (recreado por `009`, `011`, `013`); ningún endpoint actualiza `stock_actual`. Sin `inventario.productos.ver_costos` no llega `costo_ultimo` ni `costo_promedio`. Productos `tipo='servicio'` no tienen stock ni movimientos: trigger `011` (vigente en `013`) los rechaza; compras/reportes los excluyen. Movimiento `tipo='ajuste'`: `cantidad` es el nuevo stock real; trigger guarda `cantidad = ABS(nuevo - anterior)` + `stock_anterior`/`stock_nuevo`.
- Archivos privados: imágenes productos con `sharp` en `backend/storage/productos/`; endpoints autenticados `GET /api/productos/:id/imagen`, `/imagen/miniatura`. Adjuntos compras: `backend/storage/compras/`; fotos perfil: `backend/storage/perfiles/` (`/api/perfil/foto`); descarga adjuntos: `/api/compras/:id/archivos/:archivoId`. `storage/` ignorado por Git; no públicos.
- No hay alta pública de usuarios: `POST /api/usuarios` solo por administrador (decisión de diseño).
- Importar SQL con `mysql ... --default-character-set=utf8mb4` (el cliente XAMPP por defecto usa latin1 y convierte tildes a `?`). `database/scripts/025_corregir_textos.sql` corrige textos dañados, crea respaldos `_bak_*` y hardcodea `sgifep_db`.

## Sistema frontend
- SPA `base: '/usuarios/'` y `basename="/usuarios"`; Express sirve desde `backend/public/usuarios/` con catch-all `/usuarios/*`. Rutas antiguas sin prefijo (`/compras/*`, `/inventario/*`, `/reportes/*`) redirigen a `/usuarios...` para no romper marcadores.
- `src/services/api.js` lee `localStorage['session']`, inyecta JWT; ante 401 limpia sesión y redirige a `/login.html`. Sesión creada por `login.html`: `{ nombre, username, rol, roles[], superadmin, token }`.
- `vite.config.js` plugin `reescribir-rutas-sistema` (línea 10): en dev reescribe `/login.html`, `/modulos.html`, `/img/*` a `/usuarios/*`. **Debe ser plugin; `configureServer` anidado en `server` se ignora.**
- Landing `landing/src/login.js`: enlaces `data-login-url`. En dev destino real `http://localhost:5174/usuarios/login.html`; producción `/login.html`.
- Catálogo drawer duplicado: `src/config/navegacionSistema.js` (React) y `sistema/frontend/public/assets-modulos/sistema-modulos.js` + `public/modulos.html` (estático). Al cambiar rutas/visibilidad por rol sincronizar ambos lados; `backend/public/...` es copia desplegada — se regenera con `build:deploy`, no editar a mano.
- `RUTA_MODULOS_PRINCIPALES` y `RUTA_LOGIN` son absolutas (`/modulos.html`, `/login.html`); el plugin de Vite las reescribe en dev. **No prefijar con `/usuarios`.**

## Estado de módulos (lo que el agent podría olvidar)
- **Compras** implementado; flujo: Proveedores → Registrar compra → Facturas y pagos. `FlujoCompras.jsx` es indicador compartido. `/compras` (y desconocido) redirige a `/compras/facturas`.
- **Órdenes de compra**: endpoints `/api/ordenes-compra` y páginas existen, pero fuera del router y menú (módulo inactivo); no asumir que UI las expone.
- **Inventario**: reporte `/reportes/inventario` (`GET /api/reportes-inventario/resumen`); esquema `009`; permisos `010`; regla servicios `011`; **Categorías** `/inventario/categorias` (`/api/categorias`) — admin crea/edita/inactiva/elimina; compras/bodega consultan; caja/ventas/reparto no ven submenú; categoría con productos asociados no se elimina. **Productos** `/inventario/productos` (`/api/productos`) — admin/compras/bodega gestionan y ven costos; caja/ventas/reparto solo consultan (sin costos); solo admin elimina; inventario inicial genera movimiento `inventario_inicial`; no convertir producto con existencias a servicio; producto con compras/órdenes/movimientos distintos al inicial no se elimina (solo inactiva); si solo tiene inicial, se puede eliminar junto con ese movimiento. **Movimientos** `/inventario/movimientos` (`/api/movimientos-inventario`) — listado con filtros, resumen mes, registro entradas/salidas/ajustes; no se editan ni eliminan salvo `inventario_inicial` al eliminar producto.
- **Facturación**: Clientes `/facturacion/clientes` (`/api/clientes`, `014`) — predeterminado `CF` no editable ni inactivable; listado/detalle leen saldos reales desde `facturas`. Facturas `/facturacion/facturas` y `/facturacion/facturas/nueva` (`/api/facturas`, `015`) — numeración `FAC-AAAA-000000`, IVA 12%, contado/crédito, descuento stock por trigger (`origen='venta'`), servicios sin inventario, anulación solo admin con reverso (`origen='anulacion_venta'`), impresión `/facturacion/facturas/:id/imprimir`. **POS / Venta** `/pos` (ruta antigua `/facturacion/cobros` redirige) (`/api/pos`, `017`–`020`) — carrito, escáner, pago efectivo/tarjeta/transferencia, ticket 80mm, historial filtrable, anulación con reverso stock, cobros de crédito con pagos parciales, devoluciones parciales (reembolso o nota crédito); venta POS crea factura de contado pagada + cobro. Drawer: módulo principal debajo de Caja y arriba de Usuarios. Reporte ventas `/reportes/ventas` (`/api/reportes-ventas`, `020`); Auditoría `/seguridad/auditoria` (`/api/auditoria`, `020`). Carpetas `public/{compras,facturacion,despacho,reportes}/*.html` son restos estáticos sin uso.
- **Caja** `/caja` (`/api/caja`, `016`–`017`): una sesión abierta por usuario; roles `administrador`/`caja`/`ventas` consultan; `administrador`/`caja` abren/cierran. Ventas turno = ventas POS de la sesión + facturas manuales de contado (`estado='emitida'`, `creado_en >= fecha_apertura`, sin venta POS asociada), excluyen a crédito. Resumen separa efectivo/tarjeta/transferencia, suma cobros crédito y resta devoluciones; efectivo esperado `monto_inicial + ventas_efectivo + cobros_efectivo - devoluciones_efectivo`. Cierre acepta arqueo por denominaciones y montos contados de tarjeta/transferencia; guarda diferencias y detalle.
- **Perfil** `/perfil` (`/api/perfil`): nombre, apellido y correo editables; usuario de acceso solo lectura; foto privada en `storage/perfiles` servida por endpoint autenticado.

## Gotchas
- `backend/node_modules/` versionado (≈1000 archivos) pese a `.gitignore`: **no usar `git add -A`** para evitar commitear dependencias.
- `backend/public/` contiene artefactos compilados versionados; tras cambios en frontend ejecutar `npm run build:deploy`.
- Git: `main` siempre desplegable; trabajar en ramas `feature/*`; no commitear trabajo incompleto en `main`. Mensajes, comentarios y UI en español.
- Repo autocontenido aunque exista otro `sgifep-ferreteria` en disco; no tratar como monorepo.
